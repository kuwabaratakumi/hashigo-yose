# しびれろ！はしご寄席

東京・横浜・大阪・神戸の寄席の番組を、10日間分まとめて1つの画面で見るための個人用サイトです。
「はしごシネマ」「はしごミュージアム」と同じしくみ（取得プログラム＋静的サイト＋Cloudflare Pages）で作っています。

- **会場ごと** … 選んだ寄席の、その日の昼の部・夜の部などの番組（出番順・色物の種類・主任・仲入り）。名前で絞り込むと該当の出番に色が付きます
- **出演者から** … 選んだ日の、選んだ寄席の出演者を名前だけで一覧にします。名前を押すと絞り込み、その人のほかの日の出演も出します
- **はしごする** … 出演者を2〜4人入れると、その日に順番に観られる寄席と時刻の組み合わせを出します（同じ番組ならそのまま、別の寄席なら移動時間の目安を見込む）

出演者ごとの時刻（「頃」）は、番組表の時刻の区切りと出番の順から人数割りで出した**目安**です（主任は長め、仲入りは1枠）。

## 仕組み

```
各寄席の公式サイト ──(毎日2回 GitHub Actions)──> scraper/ ──> public/data/*.json ──> public/ (静的サイト)
```

- **scraper/venues.json** … 対象の寄席リスト
- **scraper/adapters/** … 寄席ごとの取得処理（`fetchRange(寄席, 日付の配列)` → `{ 日付: [公演] }`）

| 寄席 | 取得元 | メモ |
|---|---|---|
| 鈴本演芸場 (`suzumoto`) | rakugo.or.jp の日ごとの番組（`10-16.html`）と席ごとの番組（`2026-10naka-hiru.html`） | 日ごとのページがない日は「交代出演 [11,12日出演]」「[13日休演]」「[15日 ○○ 代演]」を日付で解く。3人以上の交代（`｜`）にも対応 |
| 新宿末廣亭 (`suehirotei`) | 席ごとのページ（`10naka.html`）の表 | 「交互」「〃」と出演日で解く |
| 浅草演芸ホール (`asakusa`) | スケジュールのカレンダー → 日ごとのページ（`?ca=番号`） | 「（交互）」で日付の書かれていない交代は「A／B」と並べて表示 |
| 池袋演芸場 (`ikebukuro`) | トップの席の期間 | 番組が画像のみのため、画像へのリンクだけ（出演者から・はしごの対象外） |
| 横浜にぎわい座 (`nigiwaiza`) | 公演スケジュールの月の一覧 → 公演ページの「出演」欄 | |

同じ寄席のサイトへは1ページずつ、間隔をあけてアクセスします。取得プログラムは `HashigoYoseBot/1.0 (+https://hashigo-yose.com/about.html; 連絡先)` を名乗ります（`public/site-info.js`）。

## ローカルで動かす

```bash
npm install
npm run scrape                          # 全寄席を取得（1分ほど）
node scraper/run.mjs --only suzumoto    # 1軒だけ
npm run serve                           # http://localhost:8080 で表示
```

## 公開（Cloudflare Pages）

GitHub Actions が毎日 5:10 / 13:10（日本時間）に番組を取得し、`public/` を Cloudflare Pages の `hashigo-yose` プロジェクトへ公開します。push したときも公開し直します。

初回だけ必要な設定:

1. Cloudflare で API トークンを作る（権限: アカウント → Cloudflare Pages → 編集）。はしごシネマ用のものを使い回してもよい
2. GitHub のリポジトリ Settings → Secrets and variables → Actions に登録
   - `CLOUDFLARE_API_TOKEN`
   - `CLOUDFLARE_ACCOUNT_ID`
3. Actions タブで「寄席の番組更新」を手動実行 → `https://hashigo-yose.pages.dev` で表示（独自ドメインは `https://hashigo-yose.com`。`hashigoyose.com` はこちらへ転送）

自分・社内だけで見る場合は、Cloudflare の Zero Trust → Access でこのURLに「許可するメールアドレス」を設定します。

## 寄席を追加するには

`scraper/adapters/` に取得処理を1ファイル足して `run.mjs` の `ADAPTERS` に登録し、`scraper/venues.json` に1行追加します。
`node scraper/run.mjs --only 新しいID` で取得を確認します。

候補：お江戸上野広小路亭・お江戸日本橋亭（落語芸術協会・円楽一門会の番組）、神田連雀亭、大須演芸場、国立演芸場（建て替え中）。

## 掲載中止のご依頼があったとき

1. `scraper/excluded.json` の `venues` に1件追加して push する（push の時点で公開し直されます）
   ```json
   { "id": "nigiwaiza", "name": "横浜にぎわい座", "date": "2026-10-20", "reason": "先方からのご依頼（メール）" }
   ```
2. ここに入れた寄席は、`venues.json` に残っていても取得・表示しません
3. 対応したら、依頼者に「掲載を中止しました」と返信します

## 取得できなかったときの動き

- 取得結果が0件の寄席は、公開中のサイトにある**前回のデータ**で表示を続け、画面に「最新の番組を取得できていません（○時点の情報）」と出します
- 0件の寄席が1つでもあると、公開は済ませたうえで GitHub Actions の実行を「失敗」にします（GitHub から失敗のお知らせメールが届きます）
- 同じ寄席が続けて失敗するときは、サイトの作りが変わった可能性が高いので `scraper/adapters/` の該当ファイルを確認します

## 注意

- 番組は代演・休演で当日変わることがあります。お出かけ前に公式サイトで確認してください
- 取得データの一般公開は各寄席のサイトポリシーの確認が必要です（`docs/terms-review.md`）
